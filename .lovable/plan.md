

## Problem

Cloudflare Pages detects `bun.lock` / `bun.lockb` in your repo and auto-runs `bun install --frozen-lockfile`. The lockfile was generated by a different Bun version than Cloudflare's (1.2.15), causing a hash mismatch that fails every time.

## Fix (2 changes)

### 1. Delete both Bun lockfiles
Remove `bun.lock` and `bun.lockb` from the repo. This stops Cloudflare from choosing Bun as the package manager.

### 2. Keep `package-lock.json`
The existing `package-lock.json` stays. Cloudflare will detect it and use `npm install` instead, which works reliably.

That's it. One deploy after these deletions and the build will pass.

### Technical note
The `.gitignore` should also add `bun.lock` and `bun.lockb` to prevent them from being re-committed.
